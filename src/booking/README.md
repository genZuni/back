# Booking Module

Session booking with a **trial → paid** flow and **escrow** payment release for the
1-on-1 online class platform.

## Flow

1. **Teacher availability** — a teacher publishes weekly windows
   (`dayOfWeek` + `HH:mm` start/end). Slots are generated by slicing each window
   into `Teacher.minutePerSession` chunks and removing already-booked times.
   _All wall-clock times are interpreted in **UTC**._
2. **Free trial** — a student books exactly **one** free trial per teacher
   (`Session.isTrial = true`, `price = 0`). No money moves.
3. **Unlock paid** — once the teacher marks the trial **completed**, the student
   may book paid sessions with that teacher.
4. **Paid booking (escrow)** — the student books N sessions (weekly/daily
   recurrence). For each session the price is **debited immediately** from the
   student's wallet and recorded as a **HELD** transaction (escrow) — not yet
   credited to the teacher. All sessions + holds are created in one DB
   transaction, so insufficient funds or a slot conflict rolls everything back.
5. **Completion & release** — when the teacher marks a paid session complete, the
   held payment is **released**: the held transaction becomes `accepted` and the
   teacher's wallet is credited with its own `income` transaction
   (`paymentReleased = true`, `sessionStatus = completed`).
6. **Disputes (admin)** — an admin can force-**release** a held payment or
   **refund** the student (cancelling the session).

## Endpoints (all under the global `/:lang` prefix, e.g. `/en/...`)

### Teacher (`Role.TEACHER`)
- `POST   /teacher/availability` — set weekly schedule (replaces existing)
- `GET    /teacher/availability` — my availability
- `DELETE /teacher/availability/:id` — remove one window
- `GET    /teacher/sessions?status=` — my sessions (trial + paid)
- `PATCH  /teacher/sessions/:id/complete` — mark complete + release payment

### Student (`Role.STUDENT`)
- `GET  /teacher/:id/available-slots?from=&to=` — open slots (any authed user)
- `POST /student/trial-book` — book the free trial `{ teacherId, startDateTime }`
- `POST /student/paid-book` — book paid sessions
  `{ teacherId, startDateTime, numberOfSessions, frequency? }`
- `GET  /student/sessions?status=` — my sessions

### Admin (`Role.ADMIN`)
- `PATCH /admin/sessions/:id/resolve` — `{ action: 'release' | 'refund', note? }`

## Business rules
- **No double booking** — overlap check per teacher (`assertNoOverlap`).
- **Within availability** — booked time must fit a published window
  (`assertWithinAvailability`).
- **One trial per teacher-student** — enforced in `BookingService.bookTrial`.
- **Paid gated on completed trial** — enforced in `BookingService.bookPaid`.
- **Escrow safety** — only `SCHEDULED` paid sessions release; `releaseHold`
  asserts the transaction is `HELD`; `paymentReleased` prevents double release.

## Files
- `availability.{controller,service}.ts` — availability CRUD, slot generation,
  shared overlap/availability validators.
- `booking.{controller,service}.ts` — student trial + paid booking, my sessions.
- `session.{controller,service}.ts` — teacher session list + complete, admin resolve.
- `booking.module.ts` — imports `WalletModule` for `holdBalance` / `releaseHold` /
  `refundHold`.
- `dto/` — request/response DTOs (see `dto/README.md`).

## Related
- Entities live in `src/entity/`: `session.entity.ts`,
  `teacher-availability.entity.ts`, `session-completion-log.entity.ts`.
- Escrow money logic lives in `src/wallet/wallet.service.ts`
  (`holdBalance`, `releaseHold`, `refundHold`) using the `held` transaction status.
- Schema is created automatically by TypeORM `synchronize: true` (no migrations).
